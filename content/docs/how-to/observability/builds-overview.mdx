The **Builds** page gives you a single place to see every image build that QuickStack has run or is currently running — across all projects and apps at once.

## Accessing the builds page

Click **Builds** in the left sidebar.

<img  src="/img/docs/observability/builds-overview/qs-builds.png" alt="Health Check Settings" />

The table automatically refreshes every 10 seconds while the page is open.

## Live build status

Build states are streamed in real time, so you can follow a deployment without refreshing:

- On the [project canvas](/docs/how-to/project-canvas), each app node shows its build state — **Not built**, **Pending**, **Building**, or the finished result. Apps that are building are highlighted on the canvas.
- The **Deployments** tab in the app drawer updates as the build and rollout progress.
- Changes triggered from another browser or by a webhook appear automatically.

## Viewing build logs

Click **Show Logs** on any row (where a deployment ID is available) to open the build log overlay. This is the same log viewer available from an app's **Deployments** tab.

Build logs include the **queue init container** output, so you can see when a build is waiting for a free slot as well as the actual build output. How many builds run at once is controlled by [Max Parallel Builds](/docs/how-to/admin/build-container-settings#max-parallel-builds).

## Stopping a running build

For builds in `RUNNING` or `PENDING` state, a **Stop Build** button appears if you have **Write** access for that app. Stopping a build removes the underlying Kubernetes job immediately.

<Callout>
Only builds for apps you have read access to are visible. Admin users see all builds.
</Callout>
