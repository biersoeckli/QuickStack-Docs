## Built for teams that need more control

| If you are… | QuickStack gives you… |
|---|---|
| **Outgrowing a single VPS** | A k3s cluster that can grow with worker nodes, plus Longhorn storage for multi-node volumes. Start small without choosing a dead end. |
| **An agency or team hosting separate customer workloads** | Projects, per-app permissions, and deny-by-default network policies to make isolation explicit. |
| **Working under privacy or compliance requirements** | Your application data, volumes, backups, and configuration stay on infrastructure and in the jurisdiction you choose. Use users, groups, SSO, 2FA, and scoped API keys to control access. |
| **Building with AI agents** | Experimental Agent Sandboxes with templates, warm pools, optional gVisor isolation, and LiteLLM-compatible gateways. |

QuickStack is GPL-3.0 open source: audit it, run it yourself, and move your workloads using standard Docker images and Kubernetes primitives. Read [why QuickStack](/docs/reference/comparison) or the full [security model](/docs/concepts/security-model).

## Architecture in one paragraph

QuickStack gives you the deployment experience of Vercel, Netlify, Railway, or Heroku on infrastructure you control. Push from Git or deploy a container image; QuickStack builds and runs it, handles custom domains and automatic HTTPS, and keeps backups, storage, and team access in one place. Your workloads use standard containers and Kubernetes primitives, not a proprietary runtime, so you stay free to move. Start on one server and add nodes with Longhorn storage when you need more capacity. Read the full [architecture overview](/docs/concepts/architecture).

**Under the hood:** [k3s](https://k3s.io/) · [Traefik](https://traefik.io/) · [Longhorn](https://longhorn.io/) · [BuildKit](https://github.com/moby/buildkit) · [registry](https://hub.docker.com/_/registry) · [railpack](https://railpack.com)

## History and Motivation

QuickStack started as a semester project by two students — [glueh-wyy-huet](https://github.com/glueh-wyy-huet) and [biersoeckli](https://github.com/biersoeckli) — at the [Eastern Switzerland University of Applied Sciences](https://ost.ch/).

The motivation was simple: deploying and managing applications on your own servers is harder than it should be. Existing self-hosted PaaS solutions were more focused on single node setups. We wanted something that felt as frictionless as a managed cloud platform, with the scaling and reliability of Kubernetes, but without the complexity of managing it all through the command line.

What began as an academic exercise grew into a fully-featured tool. Today, QuickStack automates the full application lifecycle: building images from Git, deploying, SSL certificates, managing volumes and backups. All through a single web UI.

The project remains open-source and community-driven. We believe that self-hosting should be accessible to everyone, not just those with deep DevOps knowledge.
